    Consume completed session work before the backendless scheduling scan
    
    A session processed by the backend-owning scan can complete its query and release its connection while retaining the work flag from the poll event. The later backendless scan then sees that same session as eligible and enters the full handler again even though its readiness and queued commands have already been consumed.
    
    Clear the work flag after a successful backend handler only when the session is waiting for client input, its current backend is detached, its frontend has no pending readiness, and its input packet queue is empty. Leave all other states and pending command work under the existing scheduling rules. Output buffered after a partial write remains registered for the next writable poll event.
    
    Use the existing work flag rather than expanding the linearly searched dispatched-session list. Preserve inline waiter handoff, shared pool behavior, and the handler epilogue that drains buffered client commands. Keep the change isolated from COPY detection and result batching so its call counts and benchmark behavior can be checked independently.
