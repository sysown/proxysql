# Unified PostgreSQL ready-loop benchmark

This is the host-specific harness for the lon104 experiment. It uses native processes and the existing `~/pg-network-bench` setup: PostgreSQL5432, TLS ProxySQL6233/admin6232, and plaintext ProxySQL7133/admin7132. Restricted existing configs and `.pgpass` supply credentials; none are embedded here.

Copy the compiled prototype to `~/pg-network-bench/src/proxysql-head-unified-ready-loop`. Retain `proxysql-head-inline-handoff` as the restore binary. The harness reads the two existing ProxySQL configs, starts one worker on CPU0, verifies native backend protocol and retention settings, and applies the requested runtime backend cap.

Run `python3 benchmark.py smoke`, then `python3 benchmark.py tls`, then `python3 benchmark.py plain`. Smoke exercises queue-only and refresh modes with single-client/simple/extended/transaction queries and deliberate disconnect cleanup. TLS mode uses50clients,64backend cap,16pgbench threads,20s warmup and60s measurement. Plain mode uses500clients,10backend cap,45s continuous runs. Both use the42-row approximately4KB workload, simple protocol and client CPUs2,4,6,8,10,12,14,16. The script verifies performance governor, TLS on both applicable hops, pool cap and zero failed measured transactions.

Each measured matrix has three repeats of the legacy scheduler, unified queue, and unified queue plus readiness refresh. All three use the same executable and differ only in scheduler environment settings. Order is legacy,queue,refresh,refresh,queue,legacy,queue,legacy,refresh. The legacy control includes the prior inline-handoff and early-dispatch changes; it is not the original a0781dd source. Mode variables are checked in the live worker environment. TLS retains free_connections_pct10; plaintext retains100. Actual pool use/creation/errors and worker CPU ticks are sampled at1Hz. TLS samples seconds5through55, plaintext10through40. Primary TPS/latency come from pgbench; CPU/query uses measured query-counter and CPU deltas in the sampled window.

Results go into a timestamped directory under `~/pg-network-bench/results`. The harness records the binary hash, git revision, raw pgbench output, settings, TLS audit, per-second samples and per-run summaries. It restores the clean inline-only binary on both listeners in a finally block. No perf attachment is used in the throughput matrix. This is an experimental single-worker/single-hostgroup study, with no multiworker or idle-migration qualification.
