# Domain docs

Use a single-context layout: root `GLOSSARY.md` and `doc/adr/`.

Before exploring, read the glossary and ADRs relevant to the work.
If these files are absent, proceed silently. Domain modeling creates
them when terms or decisions are resolved.

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the term or note the gap
for domain modeling.

Surface conflicts with an existing ADR explicitly, citing the ADR
and explaining why the decision may need reopening.
