# Issue #6118: RE2 2025-11-05 upgrade

## Goal

Upgrade the vendored RE2 engine from 2022-12-01 to the upstream 2025-11-05
release while keeping ProxySQL builds fully self-contained.

## Scope

The upgrade applies to the RE2 implementation selected by
`mysql-query_processor_regex=2` and `pgsql-query_processor_regex=2`, as well
as other ProxySQL code and tests that link `libre2`. It retains the current
RE2 public API use in ProxySQL and does not change query-rule configuration or
matching semantics.

RE2 2025-11-05 requires Abseil and C++17. ProxySQL already builds C++17 code,
but does not have a general-purpose standalone Abseil dependency. The Abseil
copy nested inside clickhouse-cpp is private to that dependency and will not
be reused or upgraded in this change.

Both RE2 and Abseil remain vendored. No system RE2 or Abseil package is needed
at build or runtime, so distribution package availability is not a ProxySQL
packaging blocker.

## Current behavior

`deps/re2/re2-2022-12-01.tar.gz` is extracted and built with the upstream
Makefile to produce `obj/libre2.a`. ProxySQL Makefiles add `-lre2` directly to
the main binary and a number of test binaries. The existing RE2 archive does
not have a separate dependency archive.

The 2025-11-05 release retains its Makefile build path, but resolves a set of
Abseil components with `pkg-config`. Its CMake build path requires CMake 3.22;
the selected integration deliberately retains the Makefile path and needs only
the CMake 3.16 required to build and install vendored Abseil.

## Design

### Vendored dependency layout

Add official source archives for RE2 2025-11-05 and Abseil 20260107.0 under
`deps/re2` and `deps/abseil`, respectively. Abseil 20260107.0 is a compatible
release pin for RE2 2025-11-05 and avoids taking the newer Abseil release that
raises the compiler floor to GCC 10.

Build Abseil as static libraries with CMake, with tests disabled and install
rules enabled, into a private prefix below `deps/abseil`. CMake receives the
parent `CC`/`CXX`, explicitly requires C++17, and propagates `STDCPP`, `WASAN`,
and `WGCOV` to C++ compilation plus executable/shared linking. ProxySQL does
not set `_GLIBCXX_USE_CXX11_ABI`, so the vendor build deliberately inherits the
same compiler default rather than introducing an incompatible override. Build
RE2's static archive through its upstream Makefile with `PKG_CONFIG_PATH`
cleared and `PKG_CONFIG_LIBDIR` restricted to that private prefix. This
supplies both the required header flags and the complete Abseil dependency set
without consulting the host package database.

The dependency Makefile will make RE2 depend on the completed Abseil install.
It will preserve `CC`, `CXX`, and ProxySQL build flags, build position-
independent objects where needed, and use only static artifacts. Existing
RE2-specific patches will be re-audited against the new source and removed
when upstream has already fixed the affected code; no obsolete patch will be
silently carried forward.

### Link integration

Define explicit Abseil and RE2 link variables in the shared Makefile path
definitions. The RE2 variable expands to the explicit vendored `libre2.a`
archive followed by the static Abseil libraries reported by the private `.pc`
metadata, in dependency order.
Replace every direct `-lre2` use and every explicit `libre2.a` dependency
where a final binary is linked with this shared variable or the corresponding
archive dependency.

This order is important: `libre2.a` must be seen before its Abseil archives.
It also keeps the new Abseil symbols resolved before optional clickhouse-cpp
archives are considered. The implementation will verify the ClickHouse build
configuration separately because clickhouse-cpp has a private Abseil copy;
the two copies are not made a shared global dependency.

Keep `RE2_PATH`, `RE2_IDIR`, and the existing `obj/libre2.a` artifact layout
where practical, so consumers continue to locate the header and archive in
the established paths. Since RE2 2025 public headers include Abseil headers,
define `RE2_IDIR` as the RE2 include path plus the private Abseil include path.
That scopes Abseil exposure to every existing RE2 header consumer without
leaking it to unrelated compilation units.

## Testing

Validate the dependency build from a clean worktree with
`PROXYSQL31=1 make cleanall` before each representative build. Run:

- the normal source build and a debug build that link `libre2`;
- RE2's upstream static test target against the vendored Abseil prefix;
- query-rule unit tests for RE2 matching and `CASELESS` replacement behavior;
- the cluster simulator and the ClickHouse-enabled build, when enabled in the
  environment, to detect link-order or duplicate-symbol regressions;
- the repository format and source-group lint checks.

CI package builds across the currently supported distro matrix remain the
authoritative cross-platform validation. Any platform-specific build-flag
adjustment must preserve the vendored-only dependency model.

The supported source tree carries one RE2 implementation at a time, so it does
not retain a second, obsolete RE2 archive in the normal build graph solely for
a runtime differential test. Compatibility is instead defined by the existing
query-rule test corpus and the stable RE2 API used by ProxySQL; the upgrade
tests exercise that corpus with the new vendored release. This keeps the
dependency graph and packaging surface to the selected, vendored version.

## Acceptance criteria

- The repository vendors RE2 2025-11-05 and the pinned required Abseil source.
- No system RE2 or Abseil package is used to build or run ProxySQL.
- Every ProxySQL binary that links RE2 also links the required static Abseil
  libraries in a correct order.
- RE2 query-rule matching and replacement tests pass, including the RE2 mode.
- Normal, debug, and selected dependency consumer builds pass after clean
  rebuilds.
